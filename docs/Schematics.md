# Визуал ранений: перевязки на костях

Перевязки крепятся к костям скелета игрока и следуют за анимацией.
Всего **36 перевязок**, 255 блоков.

## Два пути спавна

Основной - **ProjectMER (Map Editor)**: он сам занимается сетевой синхронизацией
схематика, и это работает надёжно. Запасной - свои примитивы, вкомпилированные
в плагин, на случай если ProjectMER на сервере не стоит. Путь выбирается сам,
текущий виден в `medvisual`.

### Почему вызов ProjectMER идёт через рефлексию

Прямая ссылка на ProjectMER **невозможна**, и это не вопрос вкуса.

EXILED загружает плагины через `Assembly.Load(byte[])` (см. `Loader.LoadAssembly`):

```
IL_0001: call uint8[] System.IO.File::ReadAllBytes(string)
IL_0006: call Assembly System.Reflection.Assembly::Load(uint8[])
```

У сборки, загруженной из массива байт, **нет `Location`**. Поэтому среда не может
найти по имени сборку `ProjectMER`: её грузит вообще другой загрузчик - LabAPI,
из `%AppData%\SCP Secret Laboratory\LabAPI\plugins\global\`.

Дальше - самое неприятное. Ссылка на внешний тип разрешается **при JIT-компиляции
метода**, а не при его выполнении. Метод `Spawn`, в теле которого упоминался
`ObjectSpawner`, падал с `FileNotFoundException` **до своей первой строки**, так что
ни один `VisualDebug.Step(...)` внутри него выполниться не мог.

Поверх этого обработчик команд игры гасит исключения молча:

```csharp
try { command.Execute(...); }
catch (Exception e) { sender.RaReply("Command execution failed! Error: " + ...); }
```

`Log.Error` там не вызывается. Итог: перевязки не появляются, **и в консоли нет
ни одной строки** - ровно тот симптом, который наблюдался.

> Отдельная ловушка: положить копию `ProjectMER.dll` в `EXILED\Plugins\dependencies\`
> не помогает. В процесс попадёт **вторая** копия сборки с другой идентичностью типов,
> её статический кеш схематиков будет пуст, и `TrySpawnSchematic` вернёт `false`.

**Решение - `MapEditorBridge`.** Тип ищется среди уже загруженных сборок того же
процесса, никакой загрузки по имени не происходит:

```csharp
foreach (Assembly a in AppDomain.CurrentDomain.GetAssemblies())
    if (a.GetName().Name == "ProjectMER") ...
```

Метод `TrySpawnSchematic(string, Vector3, Quaternion, out SchematicObject)` вызывается
через `MethodInfo.Invoke`; `out`-параметр приходит в массиве аргументов.
`SchematicObject` наследует `MonoBehaviour`, поэтому снаружи с ним работают как
с `Component` - этого хватает, чтобы получить `transform` и двигать схематик за костью,
ни разу не назвав тип ProjectMER в коде.

Проверка: `tools/verify_refs.ps1` читает таблицу `AssemblyRef` собранной DLL и
подтверждает, что статической ссылки на ProjectMER нет. Значит тот самый сбой
JIT вернуться не может.

### Запасной путь: свои примитивы

Все 36 перевязок оказались набором **обычных кубов**: в каждом блоке всех файлов
`BlockType = 1`, `PrimitiveType = 3` (`UnityEngine.PrimitiveType.Cube`),
`PrimitiveFlags = 2` (`Visible`, без коллизии), `Static = false`. Максимум 9 блоков
на перевязку. Поэтому геометрия продублирована в C#
(`Medical/Visuals/WoundBlockCatalog.cs`) и спавнится штатными
`AdminToys.PrimitiveObjectToy` через `Exiled.API.Features.Toys.Primitive`.

## Как это работает

### Почему координаты вокруг нуля

Схематик крепится в мировой позиции кости, поэтому блоки описаны относительно
**нуля**. В редакторе карт голова человека находится на `y ≈ 1.64`, и с абсолютными
координатами повязка оказалась бы на 1.6 метра выше кости.

Габариты частей тела взяты из `IdleHuman.json`:

| Часть | Размеры (Ш × В × Г) |
|-------|---------------------|
| Голова | 0.1336 × 0.2316 × 0.1905 |
| Торс | 0.3587 × 0.6219 × 0.2166 |
| Предплечье | 0.0793 × 0.3566 × 0.1532 |
| Бедро | 0.1536 × 0.2277 × 0.1906 |

### Почему у блоков вообще нет родителя

Касается **запасного** пути (свои примитивы). Схематик ProjectMER двигается целиком
за свой корень, там иерархию трогать не нужно.

К этому решению пришлось прийти через две неудачные попытки - обе давали
«блоки создались, но их не видно / они в башне».

Блоки синхронизируются как `AdminToy`, и `UpdatePositionServer()` публикует в SyncVar
именно **локальные** координаты:

```csharp
CachedTransform.GetLocalPositionAndRotation(out var pos, out var rot);
NetworkPosition = pos;
NetworkRotation = rot;
NetworkScale = CachedTransform.localScale;
```

**Попытка 1 - родитель пустой `GameObject`.** Клиент получает родителя по `netId`:

```csharp
if (parent != null && parent.TryGetComponent(out NetworkIdentity id))
    return id.netId;
return 0;
```

У пустого объекта `NetworkIdentity` нет → возвращается `0` → клиент цепляет блок
к `null` и трактует локальную позицию (вроде `0.1`) как мировую. Блоки в нуле карты.

**Попытка 2 - родитель корень игрока** (у него `NetworkIdentity` есть). Тоже мимо:
RPC о смене родителя уходит из `OnTransformParentChanged` и только при
`netIdentity.isServer`, то есть после `NetworkServer.Spawn`. Доставка этого RPC
в момент спавна не гарантирована (наблюдатели ещё не сформированы), и до его
получения клиент снова считает локальную позицию мировой.

**Решение - родителя нет вообще.** Тогда `localPosition == position`, и SyncVar
сразу содержит верные мировые координаты. Никаких RPC об иерархии не нужно,
а плавность даёт `NetworkMovementSmoothing`. `BoneFollower` каждый кадр пишет
мировые координаты напрямую:

```csharp
block.position = bone.TransformPoint(offset) + (bone.rotation * block.LocalPosition);
block.rotation = bone.rotation * block.LocalRotation;
```

Публиковать позицию вручную не нужно: `AdminToyBase.LateUpdate` на сервере сам
вызывает `UpdatePositionServer()`. Достаточно двигать transform.

Запись идёт в `Update`, а не `LateUpdate`: порядок вызова `LateUpdate` между
компонентами Unity не гарантирует. Ценой одного кадра задержки получаем
гарантированно верные данные.

### Кости

`BoneResolver` берёт `Animator.GetBoneTransform`. Скелет есть только у человеческих
ролей (`IFpcRole` + `AnimatedCharacterModel`), для SCP визуал не показывается.

| Часть тела | Кость | Смещение по Y |
|------------|-------|---------------|
| Head | `HumanBodyBones.Head` | +0.10 (кость в основании черепа → лоб) |
| Torso | `HumanBodyBones.Spine` | +0.15 (Spine у живота → грудь) |
| LeftArm / RightArm | `LeftLowerArm` / `RightLowerArm` | +0.12 (середина предплечья) |
| LeftLeg / RightLeg | `LeftLowerLeg` / `RightLowerLeg` | +0.18 (середина голени) |

Смещения нужны потому, что кость находится в суставе - без сдвига повязка
оказалась бы на локте или в основании шеи.

После респавна скелет собирается не сразу, поэтому визуал показывается повторно
через `WoundVisualSpawnDelay` (`MedicalManager.ResyncVisualsAfterSpawn`).

## Список перевязок

Схема имени: `Med_<Вид>_<Слот>_<Состояние>`

Левая и правая конечности используют **одну** перевязку - она зеркалится поворотом
кости, что вдвое сокращает количество данных.

| Вид | Слоты | Состояния | Итого |
|-----|-------|-----------|-------|
| `Bandage` | Head, Torso, Arm, Leg | Clean, Dirty, Blood | 12 |
| `Tourniquet` | Arm, Leg | Clean, Dirty, Blood | 6 |
| `Splint` | Arm, Leg | Clean, Dirty, Blood | 6 |
| `Burn` | Head, Torso, Arm, Leg | Clean, Dirty, Blood | 12 |

Всего 255 блоков, в среднем 7.1 на перевязку - нагрузка на сеть минимальна.

## Когда появляется перевязка

Визуал - это **бинт, а не рана**. Пока ранение не обработали, снаружи ничего не
видно: стреляют - визуала нет. Бинт появляется только после применения аптечки.

Так и должно быть по замыслу: без осмотра медиком (`medical`) диагноз не поставить,
а перевязка на модели - это отметка «рану уже обработали».

Новое попадание в то же место срывает бинт (`Injury.Reopen`), и визуал исчезает
до следующего лечения.

### Почему бинт не появлялся вообще

Самая коварная из найденных ошибок - и чисто логическая, не сетевая. В логе она
выглядела как безобидная строка:

```
[Medical:Visual] Sync Dummy: injuries 1, visuals wanted 0
```

`TreatMostSevere` заканчивался так:

```csharp
target.Treat();
...
injuries.RemoveAll(x => x.IsHealed);   // <- ранение уже выброшено
return treated;
```

а `Dress()` вызывался **после**, в `MedicalManager.Treat`. Между этими строками
ранение успевало исчезнуть: почти все ранения закрываются одной ступенью лечения
(`TreatmentSteps = 1`), а аптечка даёт ровно одну (`ItemTreatmentSteps[Medkit] = 1`).
То есть аптечка одновременно и лечила рану, и удаляла её из списка - бинт вешался
на объект, которого в состоянии игрока уже нет, а `SelectVisibleInjuries` обходит
именно `state.Injuries`. Визуал не мог появиться ни разу, ни для одного ранения.

Исправлено двумя правками:

1. `Dress()` вызывается внутри `TreatMostSevere`, **до** удаления заживших.
2. Зажившее, но перевязанное ранение остаётся в списке, пока не истечёт
   `DressingLingerSeconds` (`Injury.KeepForDressing`). Урон и эффекты оно уже
   не даёт - держится только ради бинта на модели. Тик снимает его, когда время
   вышло.

## Состояния

Состояние определяется **свежестью бинта**, а не раной:

| Состояние | Условие в коде | Что значит |
|-----------|----------------|------------|
| `Clean` | `DressedAge < DressingCleanSeconds` | Свежая перевязка (по умолчанию 3 минуты) |
| `Blood` | бинт несвежий и `IsActivelyBleeding` | Кровь проступила - **надо перевязать** |
| `Dirty` | бинт несвежий, кровь свернулась | Просто грязный бинт |

`Injury.DressedAge` растёт в тике, и когда бинт переходит границу свежести,
`WoundVisualManager` подменяет перевязку автоматически.

## Привязка к типам ранений

| `InjuryType` | Визуал |
|--------------|--------|
| `LightWound`, `CapillaryBleeding`, `VenousBleeding` | `Bandage` |
| `ArterialBleeding` | `Tourniquet` на конечности, `Bandage` на голове/корпусе |
| `Fracture` | `Splint` |
| `Burn` | `Burn` |
| `Contusion` | **нет** - ушиб снаружи не виден |
| `InternalBleeding` | **нет** - заставляет медика пользоваться `medical` |

## Оптимизация

- **Один визуал на часть тела**: показывается самое тяжёлое ранение (`Severity`).
- **Лимит `MaxWoundVisualsPerPlayer`** (по умолчанию 3): при большем числе ранений
  остаются самые тяжёлые. 40 игроков × 6 повязок - это сотни сетевых объектов.
- Флаг `Visible` без `Collidable`: повязка ни во что не упирается и не толкает игрока.
- Визуал снимается на `Died`, `Spawned`, `ChangingRole` и `Left`: при смене роли
  скелет пересоздаётся, и старые объекты висели бы в пустоте.

## Конфигурация

```yaml
show_wound_visuals: true          # включить визуал
max_wound_visuals_per_player: 3   # лимит перевязок на игрока (1-6)
wound_visual_spawn_delay: 1       # задержка после респавна, сек
dressing_clean_seconds: 180       # сколько бинт остаётся чистым, сек
dressing_linger_seconds: 300      # сколько бинт висит после заживления, сек
wound_visual_debug: true          # подробный лог каждого шага
```

Ошибки (`Log.Warn` / `Log.Error`) пишутся **всегда**, независимо от
`wound_visual_debug`: молчаливый сбой - это ровно тот баг, который здесь уже был.

## Команды

| Команда | Права | Назначение |
|---------|-------|------------|
| `.selfcheck` (`осмотр`) | - | Игрок осматривает себя |
| `medical <ник>` | `maincore.medical` | Осмотр игрока медиком/админом |
| `wound <ник> <тип> <часть>` | `maincore.wound` | Выдать ранение для проверки визуала |
| `wound clear <ник>` | `maincore.wound` | Снять все ранения |
| `medvisual [ник]` | `maincore.wound` | Диагностика: кости, каталог, счётчики |
| `medvisual test <ник> [имя]` | `maincore.wound` | Статичный спавн перед игроком, без костей |
| `medvisual bone <ник> <часть> [имя]` | `maincore.wound` | Бинт прямо на кости, следит за анимацией |

### Как искать причину, если ничего не видно

Три команды разделяют три независимые причины - идите по порядку:

```
medvisual test Dummy                     # примитивы и сеть вообще работают?
medvisual bone Dummy Torso               # привязка к костям работает?
wound Dummy VenousBleeding Torso dressed # весь путь целиком
```

1. **`medvisual test`** ставит бинт в метре перед игроком, без костей. Не видно -
   проблема в примитивах или сети, кости тут не при чём.
2. **`medvisual bone`** вешает бинт на кость и печатает `anchor world position`
   рядом с `player position`. Если anchor далеко от игрока (около `(0,0,0)`) -
   виноват поиск кости или смещение, а не сеть.
3. **`wound ... dressed`** сразу накладывает бинт, не тратя аптечку. Без слова
   `dressed` визуала не будет: необработанная рана снаружи не видна.

Лог спавна тоже печатает мировые координаты перевязки и игрока - по ним сразу
видно, оказался бинт на модели или в нуле карты.

## Пересборка

Геометрия правится в генераторе, затем переносится в C#:

```
python tools/build_schematics.py      # schematics/*.json (источник правды)
python tools/gen_block_catalog.py     # -> Medical/Visuals/WoundBlockCatalog.cs
```

`WoundBlockCatalog.cs` **не редактируется руками**. Генератор проверяет, что все
блоки остаются плоским списком кубов, и падает с ошибкой, если появится вложенность
или новый тип примитива, - то есть каталог не может молча разойтись с JSON.

Сборка сама копирует DLL в `%AppData%\EXILED\Plugins` (цель `DeployToExiled`).
Отключить: `dotnet build -p:DeployToExiled=false`.

### Сборка офлайн

`nuget.config` в корне очищает список источников (`<clear />`). Причина: единственным
включённым источником был nuget.org, и когда он недоступен, `dotnet build` висит на
«Determining projects to restore», пока NuGet ждёт таймаута HTTP.

Оба пакета заданы точными версиями и уже лежат в глобальном кеше, поэтому сеть не
нужна: restore проходит за ~200 мс, полная сборка - около 2 секунд даже после
удаления `obj/`.

Если понадобится добавить новый пакет, верните источник на один раз:

```
dotnet restore -s https://api.nuget.org/v3/index.json
```

## Что проверить в игре

1. **Позиция.** Повязка должна облегать часть тела. Если утопает - увеличить `GAP`
   в генераторе; если висит в воздухе - уменьшить.
2. **Смещение вдоль кости.** Если повязка на локте вместо предплечья - правится
   `WoundVisualCatalog.GetOffset`.
3. **Отставание при беге.** Один кадр задержки нормален. Если отставание заметное,
   стоит проверить `NetworkMovementSmoothing` (сейчас 60).
